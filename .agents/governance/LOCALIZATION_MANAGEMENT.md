# PrimeCare Global Localization & "Loose Text" Governance

This document outlines the architecture and management workflow for multi-language support (EN/FR) across the PrimeCare platform. To maintain architectural integrity and "Zero Loose Text" compliance, all developers must follow this "Registry-First" workflow.

---

## 1. The Core Architecture: "Registry-First"

Localization is not handled by manually editing JSON files. Instead, it is driven by a central governance registry.

### The Chain of Truth
1.  **Registry**: `.agents/governance/page_inventory.yaml` (Central source for all labels).
2.  **Sync Engine**: `apps/primecare_corporate/assets/translations/gen_translations.py` (Automated translation generation).
3.  **Generated Assets**: `en.json` and `fr.json` (Automatically populated).
4.  **Type-Safe Keys**: `LocaleKeys.dart` (Generated by EasyLocalization build runner).
5.  **Implementation**: UI and Adapters call `LocaleKeys.label_key.tr()`.

---

## 2. How to Manage Labels (The Workflow)

### Adding a New Label
Do **NOT** add text directly to the UI. Do **NOT** edit JSON files.

1.  **Open `page_inventory.yaml`**:
    Add your label under the appropriate section.
    ```yaml
    new_screen_labels:
      submit_button: "Submit Application"
      success_message: "Data saved successfully"
    ```

2.  **Run the Sync Engine**:
    Execute the Python script to update the French translations using the "Smart Sync" engine.
    ```bash
    python apps/primecare_corporate/assets/translations/gen_translations.py
    ```

3.  **Use in Code**:
    Import `easy_localization` and use the key.
    ```dart
    Text(LocaleKeys.new_screen_labels_submit_button.tr())
    ```

---

## 3. "Smart Sync" French Engine
The `gen_translations.py` script contains a domain-aware mapping engine that understands PrimeCare's medical, operational, and financial terminology. 
- It automatically handles complex terms like "Haversine Route Optimization" or "Zero-Day Vulnerability".
- If a term is missing, it falls back to a Google Translate API (if configured) or a standard dictionary.

---

## 4. Localizing Data Adapters (The Data Layer)
Unlike traditional apps, PrimeCare localizes labels at the **Adapter** level. This ensures that metrics, KPI titles, and insights coming from the data layer are translated *before* they reach the UI widgets.

**Requirement**: Every adapter that provides text must:
1.  Import `package:easy_localization/easy_localization.dart`.
2.  Use `LocaleKeys` for all display titles.

---

## 5. Compliance & Linting
The "Loose Text" scanner (`fix_loose_text.py`) runs during CI/CD to detect hardcoded strings.
- **Goal**: 100% localization coverage.
- **Rule**: No raw strings in `Text()` widgets or `KpiMetric` titles.

---

## 6. Future Management
As we add new roles (e.g., Clinical Director, Regional Manager), we simply add a new section to `page_inventory.yaml`. The system will automatically:
1.  Generate the French equivalent.
2.  Update the JSON assets.
3.  Expose the new keys to the Flutter app.

This ensures the platform remains "Aura-Consistent" and accessible to our global user base without manual translation overhead.

---

## 5. Leveraged Scaling (The 251-Screen Rule)
To manage 250+ screens efficiently, we do **not** edit every .dart screen file. Instead, we localize the **Registries** and **Adapters**.

*   **Registries (screen_registry.dart)**: Define the title and componentLabels for all routes. Changing one line in a Registry localizes the screen header for every user in that role.
*   **Adapters (ViewModel)**: Hydrate the dynamic data. Localizing the Adapter ensures that KPI titles, AI insights, and table headers are translated across all screens that share that data logic.
*   **Aura Engine**: The central UniversalScreenEngine automatically calls .tr() on all registry labels, ensuring global compliance.

---

## 6. Automated Compliance Enforcement
To prevent 'Loose Text' from reappearing, developers must use the enforcement tools:

*   **Deep Scan**: Run python .agents/governance/lint_loose_text.py to identify any hardcoded strings in the UI or Adapters.
*   **Summary Audit**: Run python .agents/governance/governance_summary.py to get a real-time count of registered vs. localized screens.

Any commit containing hardcoded Text('...') or title: '...' is a violation of PrimeCare Governance.
