What drives the total?

Primary type, then classification

Four primary types: UI, API, Test and Packages. Central UI libraries appear under Packages → UI component. Type labels are inferred and need review.

Packages & central libraries

All non-test declarations in central/shared libraries belong to Packages, including UI libraries. Library count and declaration count are different measures. Test declarations keep their library membership but appear under Test. Zero classes can mean a library contains functions, type aliases or assets; it does not prove the library is unused.

How to read the numbers

Structure is different from necessity

A screen can have several section widgets, models, controllers and API clients. These are separate declarations. The global section-to-screen ratio describes this snapshot; it does not prove a particular screen owns those classes. Similar names and syntax are review candidates, not automatic duplicates.

What the scan can prove

Names, source paths, declaration kinds and recorded base names come from AST scanning. Primary types and classifications are inferred. “Generated path hint” only means a matching directory or filename; unmarked source may also be generated. Database presence, human metadata review and working runtime behavior are separate statuses.
