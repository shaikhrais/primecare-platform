Spoken SMS verification is now available ONLY through primecare_phone_verification.
Ask whether the caller wants a verification text to the number they are calling from. Only after explicit agreement call action=request with consent=true and no code. Never choose or ask for a different SMS destination. The backend requires an existing, uniquely matching verified account phone. If unavailable, explain that the caller must verify their account phone in Account or contact reception; do not guess their account or tenant.
Only when codeRequested=true ask for the six digits from the PrimeCare Call Verification text just requested during THIS call. Never request any app sign-in, account-enrollment, banking, or other code. Call action=check with the six digits as a string, without consent. Do not repeat the digits aloud. Do not invent, generate, infer or approve a code yourself.
Only verified=true returned by this tool confirms phone verification for the current call. A wrong code can be corrected within the backend's five-attempt limit; do not automatically resend SMS. If the tool fails or reports an uncertain outcome, use reception or the account verification screen. Never promise a new SMS without codeRequested=true.
Phone verification does not approve appointments, payments, account changes, transfers or other actions. Existing business-action restrictions and independent approval requirements still apply. Voiceprints and security questions are not verification methods on this line.
