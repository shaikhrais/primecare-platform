Confirmed findings and implications

F01 · P0 · Production grant identities do not reconcile

The production metadata snapshot contains 192 distinct grants: 64 each for API710, API857 and API777. Of those, 128 have labels for operations different from the message endpoints; all 192 refer to missing runtime artifact 1. These are overlapping findings, not 320 separate grant rows. API777 already has its correct preference key. Registry IDs 710/857 refer to endpoint IDs 4957/5104, which were absent from the endpoint readback. Numeric registry IDs must not be treated as endpoint IDs.

Repair: R01: reconcile original authority and exact row provenance; prepare a per-row before/after proposal. Do not blindly relabel, move grants, clear artifact references, invent artifacts, add roles or change quarantine.

Evidence: docs/appearance/theme-release-identity-readback.json; scripts/check-api-catalog-identity.py; CI 41346724602 / job 124968025068

F02 · P0 · Source acceptance and publication have diverged

Tenant/PSW acceptance succeeded at 4c238052. Its publication job failed because main advanced to 83acb26c. The source comparison shows only two documentation files changed, but the publication guard compares the entire commit. This is a correctly enforced stale-source guard, with a scheduling/coordination consequence. Repeated documentation pushes can leave accepted code unpublished. The separate production grant blocker remains independently open.

Repair: R03: select the exact latest release candidate, finish required verification, publish that same immutable candidate, then record acceptance. Queue/retry stale candidates through a fresh verified run; retain both current-main checks.

Evidence: .github/workflows/psw-workspace.yml:85 and :113; CI 41346938090 / failed publish job 124969228064

F03 · P1 · Shared implementation is much broader than actual host adoption

Static constructor scanning found one web composition of PrimeWorkModule/TenantTaskModulePort, in the existing tenant pilot, and no direct constructors of the assessed new workspace/navigation/work/communication/application adapters under the native apps or shared registry. This is bounded source evidence, not proof that no dynamic composition exists. The native usage guide explicitly states that existing shells do not opt in automatically. Tests and exports therefore cannot establish app-wide adoption.

Repair: R04/R05: build a per-app route-to-composition-to-adapter manifest, including dynamic registry resolution; bind registered hosts and verify actual routes before migration.

Evidence: websites/typescript/src/tenant-dashboard/work-module-host.ts; docs/appearance/native-workspace-usage.md; docs/appearance/developer-catalogue.md

F04 · P1 · Preference service is deliberately gated and does not cover the pilot roles

The handler requires PREFERENCE_SYNC_ENABLED=1, exact reviewed endpoint metadata, an active role and its API777 grant. The retained documentation says runtime is disabled, grants cover role IDs 1–64, Tenant Admin and Code Admin remain denied, and no registered panel bindings exist. Thus registering theme controls on Tenant Admin does not make account cloud preferences functional. Current secret/runtime flag values were not freshly queried during this assessment.

Repair: R02/R06: resolve actual raw-role/host authority, register panel references and intended preference kinds, wire explicit recovery, and enable only after exact authorization and deployed acceptance.

Evidence: cloudflare/workers/src/account-preferences.ts:16 and :43–48; docs/appearance/preference-sync-usage.md; tools/governance-production/preference-sync-contract.json

F05 · P1 · The five work views implement task-backed subsets

Contacts is a read-only projection of users/clients. Notes edits task notes. Calendar changes task due dates. Board follows task transitions. This is useful reuse, but does not implement standalone contact/notes CRUD, timed appointments, recurrence, reminders, custom board lanes/ranking or new-template creation receipts. The broader platform may have related services; no platform-wide absence is claimed.

Repair: R08: reuse confirmed existing workflow contracts where equivalent; implement the missing domain flows only after request/response, authorization, persistence and receipt mapping.

Evidence: packages/shared/src/work-modules/tenant-task-adapter.ts; packages/flutter_core/lib/work_modules/tenant_task_module_port.dart; docs/appearance/theme-gap-register.md B13

F06 · P1 · Communication templates omit full workflows

The collection adapter exposes existing message inbox/read/send/mark-read and owned mailbox reads. Its type explicitly excludes notifications; files project attachment references. These new templates do not yet supply general file storage management, mailbox compose/drafts/folders/delivery UI, full conversation creation/history/realtime/presence/call UI or a self-notification binding. Existing communications channels and provider services must be reused, not duplicated.

Repair: R09: map registered service operations to the inherited shared adapters; implement provider receipts, storage policies and real host flows with owned/cross-tenant denial.

Evidence: packages/shared/src/communications/module-port.ts; packages/primecare_ui/web/communication-modules.ts; packages/shared/src/communications/AGENTS.md

F07 · P1 · Several application/dashboard families are intentionally unavailable

Profile is read-only identity and settings manages shortcut preferences. Academy, commerce, AI images and help require additional confirmed workflows/providers. Dashboard projection supports project/analytics counts but explicitly returns unavailable for finance/crypto; invoice/pricing/authentication supporting-page statuses are also unavailable. These are missing integrations/features, not rendering regressions.

Repair: R10: confirm learning/help/finance/commerce/provider contracts and entitlements, reuse existing account flows, and complete genuine business flows without invented metrics or fixture success.

Evidence: packages/shared/src/application-modules/profile-port.ts; packages/shared/src/application-modules/settings-port.ts; packages/shared/src/dashboard-pages/projection.mjs; packages/shared/src/dashboard-pages/supporting-pages.mjs

F08 · P1 · Advanced controls and widget persistence are incomplete

Remaining B10 scope includes character-range rich-text marks/HTML import policy, spreadsheet/server query adapters, specialized rating/slider/stepper/transfer controls and production binary storage/picker adapters. The chart model accepts line, area, bar and donut, with metrics; free-coordinate grid editing and additional chart families remain outside the implemented subset. B11 has no registered dashboard preference document kind or complete authoritative widget mappings.

Repair: R07: specify each remaining variant, add shared web/native implementations and authorized persistence, and test real data/removal/readback. R06 must establish the dashboard document policy first.

Evidence: packages/domain/src/data_controls.ts; packages/domain/src/dashboard_widgets.ts; docs/appearance/theme-gap-register.md B10/B11

F09 · P1 · Durable restart recovery remains distinct from in-session retry

WorkModuleSession keeps the pending command, request key and acknowledgement in memory. The verified retry path avoids duplicate mutations after a failed readback. Disposing/restarting still clears this context; a durable restart journal/reconciliation flow is not implemented by that repair. Pending state must remain bound to tenant/user/raw role/dataset and receipt lifetime.

Repair: R06: add a scoped versioned pending-command journal and explicit restart reconciliation; test crash after send, lost acknowledgement, acknowledged/readback failure, receipt expiry, logout, revoked access and storage failure.

Evidence: packages/shared/src/work-modules/session.ts; packages/flutter_core/lib/work_modules/work_module_session.dart; docs/appearance/theme-gap-register.md

F10 · P2 · Localization and terminology do not match complete rollout

The actual tenant work host hardcodes locale en. Generic pagination controls reuse Previous month/Next month translations even for non-calendar views. EN/FR/ES metadata exists, but translation presence is not reviewed business localization or whole-app RTL/accessibility acceptance.

Repair: R04/R11: propagate authenticated locale, register contextual pagination labels, and verify direction, date/number formats, keyboard/focus and screen-reader flows in real hosts.

Evidence: websites/typescript/src/tenant-dashboard/work-module-host.ts:23; packages/primecare_ui/catalogs/work-modules.registration.json; tools/governance-production/work-modules-contract.json
