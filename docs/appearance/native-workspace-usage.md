# Optional native workspace renderer

Implementation status: source implemented, host activation and independent release review pending.

Use `package:flutter_core/workspace.dart` or `package:primecare_ui/workspace.dart`. This is the shared presentation engine, not a new screen or a replacement route. No existing native shell opts in automatically. A live host must first register its native control/component/source bindings in the pinned production governance authority, then supply only its existing authorized navigation, toolbar, content, footer and panels. The B01/B02 metadata receipt proves a TypeScript host; it does not authorize a native host.

Create and own one `WorkspaceController` per authenticated tenant/user/role/dataset. Supply an immutable current authorized panel registry and a `SharedWorkspacePreferences` adapter backed by the app's existing preferences instance. Call `load()` before showing saved geometry; dispose the controller on identity changes. Create a new controller when permissions remove panels. Never reuse a controller across accounts or build it afresh on every widget render.

`PrimeWorkspaceLayout` takes that controller and the existing widgets as slots. Optional `WorkspaceHandleLabels` must come from the host's registered localized resources. The factory preserves slot state through global-key reparenting within the same controller and destroys that state when the controller identity changes. Main and panel slots receive bounded dimensions, so scrolling children such as lists and forms can be supplied directly.

The advanced JSON is the same data-only v1 contract as `packages/domain/src/workspace_layout.ts`: navigation position/width; toolbar position and scroll behavior; footer behavior; container/max width; page/content scrolling; and permitted panel dock, x, y, width and height. Import rejects unknown/missing fields, authority fields, invalid dimensions, unknown panel identities and UTF-8 files larger than 32 KiB. Export contains geometry and permitted panel identities, never account credentials, business records, routes or permissions. Rendering clamps geometry to the available safe area without rewriting the stored profile.

Desktop and wide tablet handles accept mouse/touch dragging, arrow movement, Shift+arrows for resizing, Control/Command+arrows for docking, and Escape to cancel. A complete gesture is one history entry; cancelled gestures add none. Accessibility increase/decrease actions provide an additional keyboard/screen-reader path. At viewport widths of 1024px or less, panels stack and free-drag handles are disabled, matching the web fallback; the profile retains its desktop geometry. Dock selection can still be applied by the registered host's presentation controls.

`change`, `patch`, `dock`, `undo`, `redo`, `reset`, `importJson` and `exportJson` are synchronous validated presentation operations. `load` and `save` use the one scoped adapter. Storage failures are returned to the host; a late load cannot replace newer edits or update a disposed account. Preferences are device-local; cross-device synchronization is B07.

Existing native theme choices remain intact. The optional `legacyLayoutStyle` argument copies only the already-loaded current actor's left/right/top presentation choice into a fresh advanced default. It never reads, overwrites or deletes legacy theme settings or the historical role-only `pref_layout_*` store. Collapsed/compact navigation remains a host chrome choice, as on the web; it is not silently added to the strict advanced JSON contract. Legacy theme/XML handling remains in the existing theme managers.

Validation: generate the shared oracle with `node scripts/workspace-native-contract-fixtures.mjs`, run `flutter test test/workspace` in `packages/flutter_core`, then run the Node script with `--verify-native`. CI runs analysis and the contract/controller/widget suite on Linux, Windows and macOS, verifies each native export with the actual web validator, and compiles a disposable host containing the actual renderer to Flutter web. These checks are not proof of a registered native host, an Android/iOS device session, human translation approval, or production-ready status.
