# Read-only dashboard and record host ownership

The common `bindReadPage` lifecycle powers dashboard, activity and search host bindings. Its cleanup was repeatable and always cleared the root, so an old cleanup handle or queued draw could remove/repaint a replacement page. Failed construction also left partial output/subscriptions, and session disposal could synchronously mount a new owner that the old cleanup then cleared.

Track the current root owner in a weak map. Only its live draw callback may render; each cleanup runs once, disposes only its captured session and clears the root only while that owner still holds it. A newer binding takes presentation ownership without implicitly disposing a caller-owned older session. Failed initial drawing/load startup unsubscribes when acquired, restores the prior live owner and original child nodes, and leaves the failed caller-owned session available for explicit cleanup/retry. Reentrant replacement during cleanup is preserved. Already-retired prior owners are not revived by failure rollback.
