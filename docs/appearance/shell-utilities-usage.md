# Shared shell utilities integration

B08 adds optional shared web/Flutter utility drawers, resource acknowledgement state, searchable favourites, fullscreen ports and scoped direction/scroll handling. Source ownership is `primecare_ui` plus the shared utility controller. Human release ownership/review remains unassigned. Dependencies are B01 metadata, B04 authorized navigation, B05 authorized host/route composition, B06 theme tokens and B07 account preference sync.

Production registration run `41251351703` at `6abf5e8822d399f981094701777f2753379503c0` registered 21 optional controls and 31 resource keys with 93 EN/FR/ES translations on existing screen 2534, Tenant Admin. Independent readback verified the committed records; no screens, APIs, grants, business rows or runtime activation were added. All controls remain `registered-unimplemented`; translations remain unreviewed/unapproved. The export is `packages/primecare_ui/catalogs/shell-utilities.registration.json`. This pilot registration is not authority to mount the utility in other hosts or native apps.

Use `packages/primecare_ui/web/shell-utilities.ts` or `package:primecare_ui/shell_utilities.dart`. Construct exactly one actor-bound `ShellUtilitiesController` with the current full tenant/user/raw-role/dataset scope, an existing B07 `shortcuts/navigation` sync client, and currently authorized numeric screen IDs/destination labels. Navigation callbacks accept IDs only and must resolve them through the current B04 server-authorized registry. Disabled destinations cannot be opened or favourited. Saved preferences never grant access.

Resource ports for events, notes, quick settings and notifications must wrap existing authorized adapters. Each loader returns at most 100 strict projected records `{id,title,detail,read,status}`, where read/status are explicitly null when not supplied by the source. Do not attach business endpoints merely because their names resemble an item. A missing port displays unavailable; a failed request displays error, never successful demo or empty content. Notification delivery/status is shown only when the adapter supplies it. Read/unread controls require a registered mutation port returning the exact updated record, ID and confirmed read state. Failures retain the prior confirmed value. `activate` is for an already-authorized host navigation/action callback; it is not a background mutation queue.

The production discovery found legacy notification POST declarations with no approved self-notification read/unread contract for these shell controls. The source's older `/v1/auth/me/notifications` repository is not assumed to be a registered B08 binding. Live notification mutations, events/notes and delivery integrations remain unbound. Business resource tests in this batch deliberately use synthetic adapters and do not claim production delivery or notification writes. No new APIs or role grants are silently created.

Favourites use B07 directly: load before editing, save explicitly, display dirty/offline/error/conflict states, and retry pending requests only on explicit action. A conflict offers server or local resolution. The B08 browser fixture exercises the real registered preference gateway/handler with disposable PostgreSQL, independent SQL readback, a second isolated browser account session and reload. Production B07 remains disabled and grants only its existing roles 1–64, excluding Tenant Admin and Code Admin; the optional pilot controls must not be activated as if this limitation were solved.

Web requires a distinct utility slot inside a scoped shell element and inherited B06 design tokens. `ShellUtilitiesView` owns only that slot. Its modal uses registered labels/IDs, keyboard tab navigation, logical RTL placement, focus restoration, bounded search and text-only rendering of record labels. The controller and view are immutable per actor. On web, the view owns the controller; dispose it through the view before replacing account/tenant/role state. Do not share a controller across independently disposed views. Late requests are ignored. Await `view.dispose()` before reusing its shell root because browser fullscreen operations may still be settling.

`ShellEnvironment` changes only its scoped root's direction and scrollbar colors, restores original values at disposal, and refuses document/body roots. Route resets occur only when the host calls `routeChanged()` with a changed registered route identity; ordinary rerenders retain scroll and business form input. Only owned descendant scroll roots may be reset. No global route listeners or document styles are hijacked. Custom scrollbar CSS has standard and WebKit implementations; browsers that do not support them retain their native scrollbar.

Fullscreen requests must originate from a user action, be supported by the browser and be confirmed through the actual `fullscreenElement`. Rejection remains an error. The adapter never exits fullscreen owned by another element. Flutter has no pretend default OS fullscreen implementation: the control is disabled unless a host supplies an approved `ShellFullscreenPort` with an actual-state reader and confirmed state writer. Flutter layouts use ambient theme styling and explicit host token-derived width; RTL direction and scrollbar orientation mirror correctly. `PrimeShellScrollRegion` owns route-keyed scroll state independently of child form state. The launcher retires its owned dialog on controller replacement/disposal; authenticated hosts must close it before transitioning identities and dispose the old controller and await its preference client's `settled` cache-write future before reusing the same account scope.

Before rollout: register each actual web/native host/source/control binding, bind and verify business adapters and any reviewed notification API mutations, reconcile the Tenant Admin/API 777 access mismatch through an explicit governance decision, provide stale-preference recovery UI, and complete device, keyboard/screen-reader, EN/FR/ES and human release review. Broader governance consumer-cutover blockers from B07 remain. No whole-app RTL, physical-device, Cypress production acceptance or all-app activation is claimed.
