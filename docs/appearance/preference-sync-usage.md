# Account preference sync integration

The shared source supports API 777, POST `/v1/user/preferences`, for `theme/advanced-v2`, `shortcuts/navigation`, and a role-viewable registered workspace screen code. Import `packages/primecare_ui/web/preference-sync.ts` or `package:primecare_ui/preference_sync.dart`. Runtime exposure remains disabled pending registration and release review. This module does not mount new controls or grant access.

Construct one immutable `PreferenceBinding` per current authenticated tenant, user, raw role and live/demo dataset, plus the host's already-authorized panel/screen registry. Use one session-captured `preferenceHttpTransport` and `preferenceStorageCache(localStorage)` on web. Flutter uses `PreferenceHttpTransport` and `SharedPreferenceCache`. The server derives identity independently and treats `expectedScope` solely as a precondition. Dispose the client and close its transport at logout or role/tenant/session changes. Never reuse a client across identities.

Call `load()` before edits. Inspect `current.status/error`; a resolved Future is not proof of a successful network save. `edit(document)` validates and caches the draft. `save()` queues the exact revision and UUID durably before sending. A failed mutation remains pending and is retried only through explicit `retryPending()`. A lost acknowledgement replays the original receipt. An edit made during a save stays dirty. Refresh does not replace a dirty draft. On conflict, show the current owned server value and offer `acceptRemote()` or `keepLocal()` before a new save. Local resolution is explicit and does not itself write the server.

For defaults, call `edit(null)` then `save('reset')`; `save('delete')` removes the value in the same monotonic way. A null document means the host derives current tenant defaults. Tombstones prevent stale revision-zero clients recreating old settings. `discardLocal()` removes only this account/role/dataset/resource cache. Logout should dispose the client before discarding authenticated host state; scope-keyed drafts persist unless the host's approved privacy policy removes them.

`adoptLocal(document, provenScope)` accepts only a matching, fully proven account scope and a current-format document with no existing remote value or draft. Never auto-import old role-only keys. Unsupported versions, malformed caches, denied storage, stale references and invalid responses remain errors. Hosts must offer explicit local discard/reload recovery; never silently erase a user's failed draft or report a cloud save while offline. Translation resources and UI bindings are separate release gates.

The server validates registered current API grants, active roles/screens and shortcut references. There are currently no registered panel bindings for API 777: workspace documents must have an empty panel map. Existing pilot DOM panel names do not constitute registration. Revoked references are rejected before client application; resolving settings with obsolete panel/screen IDs requires explicit recovery and cannot confer permissions.

Runtime activation requires both `PREFERENCE_SYNC_ENABLED=1` and the exact endpoint's reviewed `implemented-unverified` marker. Production remains `registered-unimplemented` with no flag enabled. Existing API grants cover roles 1–64 only; Tenant Admin and Code Admin remain denied. Do not add grants or enable the runtime through application defaults. Live deployment, host control registration, localization, accessibility and human release review remain outstanding.

The contract enforces 72 KiB requests, 64 KiB documents, 120 reads/minute, 30 mutation attempts/minute per account and 300 requests/minute per source. Failed mutation attempts consume quota. IP-derived keys are hashed, stale rate rows expire after two minutes; receipts expire after 24 hours and retain at most 100 per actor scope. A retry after receipt expiry safely conflicts if the original mutation committed. Audit records contain identity, action, revision and a SHA-256 document digest, never document values. Account and tenant deletion cascade stored settings and receipts/audit records.

Validation commands: `node scripts/test-preference-client.mjs`, `node scripts/test-preference-registration.mjs`, `node scripts/test-preference-service.mjs`, and `node scripts/test-preference-browser.mjs`. Set only a dedicated loopback `PREFERENCE_TEST_DATABASE_URL` ending in `/preference_test` for native PostgreSQL tests. Fixtures refuse production credentials and synthetic accounts never reach production. Flutter: `flutter test test/preference_sync`; CI also analyzes and tests Linux, Windows and macOS.
