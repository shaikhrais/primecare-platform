# Account preference sync integration

The shared source supports API 777, POST `/v1/user/preferences`, for `theme/advanced-v2`, `shortcuts/navigation`, and a role-viewable registered workspace screen code. Import `packages/primecare_ui/web/preference-sync.ts` or `package:primecare_ui/preference_sync.dart`. The production proof covers owned shortcuts in Tenant Admin Settings. Each additional host requires its registered controls, appropriate existing access and release evidence.

Construct one immutable `PreferenceBinding` per current authenticated tenant, user, raw role and live/demo dataset, plus the host's already-authorized panel/screen registry. Use one session-captured `preferenceHttpTransport` and `preferenceStorageCache(localStorage)` on web. Flutter uses `PreferenceHttpTransport` and `SharedPreferenceCache`. The server derives identity independently and treats `expectedScope` solely as a precondition. Dispose the client and close its transport at logout or role/tenant/session changes. Never reuse a client across identities.

Call `load()` before edits. Inspect `current.status/error`; a resolved Future is not proof of a successful network save. `edit(document)` validates and caches the draft. `save()` queues the exact revision and UUID durably before sending. A failed mutation remains pending and is retried only through explicit `retryPending()`. A lost acknowledgement replays the original receipt and preserves any newer cached draft, including after a restart. An edit made during a save stays dirty. Refresh does not replace a dirty draft. On conflict, show the current owned server value and offer `acceptRemote()` or `keepLocal()` before a new save. Local resolution is explicit and does not itself write the server.

For defaults, call `edit(null)` then `save('reset')`; `save('delete')` removes the value in the same monotonic way. A null document means the host derives current tenant defaults. Tombstones prevent stale revision-zero clients recreating old settings. `discardLocal()` removes only this account/role/dataset/resource cache. While storage removal is pending, status is `discarding` and edits, reloads and mutations are blocked. A failed removal retains the draft and reports `cache_unavailable`; a late completion cannot revive a disposed client. Logout should dispose the client before discarding authenticated host state; scope-keyed drafts persist unless the host's approved privacy policy removes them.

`adoptLocal(document, provenScope)` accepts only a matching, fully proven account scope and a current-format document with no existing remote value or draft. Never auto-import old role-only keys. Unsupported versions, malformed caches, denied storage, stale references and invalid responses remain errors. Hosts must offer explicit local discard/reload recovery; never silently erase a user's failed draft or report a cloud save while offline. Translation resources and UI bindings are separate release gates.

The server validates registered current API grants, active roles/screens and shortcut references. There are currently no registered panel bindings for API 777: workspace documents must have an empty panel map. Existing pilot DOM panel names do not constitute registration. Revoked references are rejected before client application; resolving settings with obsolete panel/screen IDs requires explicit recovery and cannot confer permissions.

Runtime activation requires both `PREFERENCE_SYNC_ENABLED=1` and the exact endpoint's reviewed `implemented-unverified` marker. The [owned PC10 activation receipt](pc10-preferences-activation.json) records both conditions and deployed save, independent SQL readback, reload and cross-account denial for the Tenant Admin shortcut editor. The [grant repair receipt](theme-auth-preference-repair-evidence.json) records 67 existing self-preference grants, including Platform Admin 70, Tenant Admin 72 and Code Admin 80. They scope preferences to the authenticated actor, tenant, active role and dataset. Broader host binding, device and human release evidence remains open.

The contract enforces 72 KiB requests, 64 KiB documents, 120 reads/minute, 30 mutation attempts/minute per account and 300 requests/minute per source. Failed mutation attempts consume quota. IP-derived keys are hashed, stale rate rows are cleaned opportunistically on requests after two minutes; receipts expire logically after 24 hours and are cleaned on subsequent mutation requests and retain at most 100 per actor scope. A retry after receipt expiry safely conflicts if the original mutation committed. Audit records contain identity, action, revision and a SHA-256 document digest, never document values. Account and tenant deletion cascade stored settings and receipts/audit records.

Validation commands: `node scripts/test-preference-client.mjs`, `node scripts/test-preference-registration.mjs`, `node scripts/test-preference-service.mjs`, and `node scripts/test-preference-browser.mjs`. Set only a dedicated loopback `PREFERENCE_TEST_DATABASE_URL` ending in `/preference_test` for native PostgreSQL tests. Fixtures refuse production credentials and synthetic accounts never reach production. Flutter: `flutter test test/preference_sync`; CI also analyzes and tests Linux, Windows and macOS.

Example mutation (identity fields must match the authenticated session; these are illustrative placeholders, not registered account records):

```json
{"version":1,"action":"write","expectedScope":{"tenantId":"current-tenant","userId":"current-user","role":"current-role","dataset":"live"},"dataset":"live","kind":"shortcuts","resource":"navigation","revision":0,"requestId":"00000000-0000-4000-8000-000000000001","document":{"version":1,"screenIds":[]}}
```

Read uses the same scope, dataset, kind and resource with `action: "read"` and omits revision, requestId and document. Error responses contain an error code; revision conflicts additionally include the current owned snapshot. Reset and delete omit document and require the last observed revision plus a new request UUID. A stale-reference error must remain visible; the shared client does not automatically repair cloud data whose referenced controls/screens have since been revoked. A governed host recovery flow must explicitly read the owned revision and confirm a reset without applying revoked references before rollout.

Source ownership is the shared preference module; human release ownership/review remains unassigned. Dependencies are B01 registration, B02/B03 workspace contracts, B04 navigation allowlists and B06 version-2 themes. No separate business screen or workflow is created by these adapters.

## Existing tenant default-view form

The tenant dashboard's default-view preference uses its existing business API and form, independently of API777. `TenantPreferenceDraft` keeps the unsaved view and its original server revision in a browser cache keyed by tenant, user, role and live/demo dataset. Failed saves and redraws retain the choice; reload restores the draft without silently rebasing it over a newer server revision. A successful acknowledgement clears only the submitted draft, retaining a newer choice edited while that save was pending.

The existing Refresh button offers explicit local discard before reloading a pending draft. Corrupt caches and revoked views cannot be submitted silently; cache failures retain the tab's draft and remain visible. Server authorization and optimistic version checks still decide every save. This cache scope does not change the existing business API's server storage contract or enable global theme/layout/shortcut cloud sync. This form now persists the exact pending request ID and body before dispatch. Loading only reads; Save explicitly retries that original request, including its captured demo workspace version, before a newer edit can be submitted. An uncertain pending request cannot be discarded silently. Definitive rejection (or a revoked pending view) permits explicit local discard with Refresh. Receipt replay is checked against native PostgreSQL revisions and audit-event counts. Durable reconciliation for other commands/native hosts and reviewed localization remain open R06 work.
