# B02 — shared web layout integration

The existing Tenant Admin command center now explicitly mounts the registered workspace controls through the shared shell and Theme Center. Other portals can reuse the shared integration, but are not opted in by this change. This is a host pilot, not full theme adoption.

The UI consumes the independently verified control IDs and EN/FR/ES labels from `theme-workspace.registration.json`. Its `runtimeEnabled:false` value deliberately means that metadata export alone never activates a host. The tenant entry point supplies its trusted host code, server-returned organization/user/role/dataset scope, and the already-rendered preference card. No routes, APIs, business widgets or permission grants are added.

Supported in the pilot: navigation left/right/top/bottom/hidden and width; content container and maximum width; toolbar position and sticky/static behavior; page/content scrolling; the existing preference card docked, floating, hidden, moved or resized with pointer/keyboard; undo/redo/reset; browser-local save; strict JSON import/export. Legacy theme XML remains separate. Footer controls are registered but disabled because this host has no independent footer slot; the existing status/error output is not hidden or repurposed as one.

The shell restores nodes through comment anchors before rerendering, retains layout history only within the same account scope, and reattaches only the panels actually supplied by the current render. It releases observers/listeners on root replacement and page exit. Layout changes move the original DOM nodes, preserving unsaved values, focus and business handlers. Small screens retain the existing drawer and stack panels; drag/resize handles are disabled there. Navigation layout families and horizontal-menu refinements remain B04.

Validation uses the actual Tenant Admin entry point, shared shell, service, and a disposable PostgreSQL-compatible database, not a synthetic dashboard rendering. `scripts/test-tenant-workspace-layout.mjs` checks navigation/layout controls, history across refresh, original node/handler retention, actual preference-save SQL readback, storage failure, JSON rejection, XML download compatibility, reload persistence, account isolation, mobile navigation and EN/FR/ES reconstruction. The shared engine suite additionally exercises 60 browser geometry combinations, pointer/keyboard/cancellation, viewport bounds and disposal; the domain suite validates 180 configurations and rejects unknown panels/authority fields.
