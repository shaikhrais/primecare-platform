# Shared navigation and preset compositions

Implementation status: opt-in source factories; production host/control bindings and independent release review remain required.

The web entry is `packages/primecare_ui/web/workspace-navigation.ts`; native entries are `package:flutter_core/workspace_navigation.dart` and `package:primecare_ui/workspace_navigation.dart`. Existing shells are not automatically replaced. No screens, business destinations, APIs or role grants are created by these libraries.

Build the model from current server-authorized metadata. Supply both the permitted stable node IDs and the permitted exact route strings, plus registered icon IDs. The factories validate the complete tree, reject duplicate identities, unsafe URLs, unregistered icons, unknown fields, invalid text, excessive depth and excessive node count, then intersect IDs and routes. A denied parent removes its entire subtree. A disabled parent disables its descendants. Empty groups are omitted. This is presentation filtering, not a replacement for server authorization.

Use existing IDs unchanged, including registered screen codes containing underscores. Nodes contain `id`, `kind` (`item` or `group`), `label`, optional `icon`, `subtitle`, `badge`, `disabled`, route `match` (`exact` or segment-boundary `prefix`), and either `route` or `children`. Badge values and labels must already be scoped by the server. Do not reconstruct roles, grants or business counts in the widget.

Three original presets use the same strict workspace layout: `vertical` places navigation at the side, `horizontal-header` places it above content, and `horizontal-footer` places it below content. `navigationPreset` returns a validated profile preserving existing panels, dimensions and other settings; apply it through the existing workspace controller/manager. Pass the same family to the navigation renderer. A preset never changes the authorized tree.

The web `WorkspaceNavigationView` owns an exclusive connected navigation host. Its options include the current actor scope, raw items, authority, current relative route, localized labels, family, mode and the existing host navigation callback. Icons are resolved by a trusted registered-icon renderer. Text is assigned as text, never interpreted as HTML. Optional `frame: {element, profile}` connects folded presentation to the shared workspace frame: it temporarily projects a 64px unpinned rail and restores the saved width on hover, focus, pinning or disposal. It does not rewrite the saved profile or add history entries for pointer hover.

Horizontal dropdowns use an owned overlay outside sidebar overflow containers, with viewport bounds and RTL placement. Keyboard arrows, Home/End, Tab and Escape operate on the current model. Folded navigation expands for hover and focus; pinning keeps it expanded. Rail tabs select a group/submenu panel, and a route change selects its current root group. Mobile uses a focus-trapped drawer. Updating scope or authority revokes old DOM callbacks and hrefs before detaching the old entries. Invalid replacement metadata clears managed entries before returning the error; a later resize cannot rebuild the old permitted tree. Disposing removes the overlay/listeners and leaves an empty host; rebuilding current navigation belongs to its owner, so old-account HTML is never restored.

The Flutter `PrimeWorkspaceNavigation` takes a validated immutable model, scope, current route and localized labels. It uses shared Material horizontal menus, controlled nested vertical disclosures, a selected icon rail and a responsive dialog drawer. Horizontal navigation has a visible keyboard entry: Tab to the navigation, then Enter, Space or Up/Down opens the menu bar; arrow keys traverse the current nested menus and Escape dismisses them. Material keeps menu items unfocusable while the bar is closed, so hosts must retain this entry control. Desktop and drawer focus nodes have separate ownership; model/scope replacement closes old overlays and generation checks reject old activation callbacks. Existing content and navigation callbacks remain owned by the host.

For a folded native composition, connect `onExpandedChanged` to `PrimeWorkspaceLayout.navigationVisualWidth`: use 64 when vertical/folded/unpinned and not expanded, otherwise use the controller's saved navigation width. Keep this as transient presentation state. The JSON contract still stores the valid expanded width and all business form state remains in the supplied content slot. Scope changes must create or reset the owner state as described in the native workspace usage guide.

Labels are supplied by the host's registered EN/FR/ES resources. Pin/unpin and new group/rail controls must have verified host/component/resource/source bindings before live exposure. The B01/B02 TypeScript pilot receipt alone does not authorize these new controls or a native host. Navigation preferences are not synchronized across devices here; that remains B07.
