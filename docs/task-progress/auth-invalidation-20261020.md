# Auth invalidation repair and verification — 2026-10-20

Password changes, recovery resets, CEO account edits and single-session logout previously acknowledged success without verifying complete session invalidation. Password changes and resets also did not verify that every reset-code record had been removed. A real PostgreSQL trigger that suppressed one deletion reproduced these failures in both text and UUID identity schemas.

The shared helper deletes the intended records and validates a native Boolean `EXISTS` result. Password changes, resets and account edits run under their existing user lock and transaction, so an incomplete deletion or invalid result aborts the complete mutation and audit. Logout confirms that its submitted token is absent before clearing the cookie; a failed check returns503 without a success cookie, and a retry preserves the account's other session. No endpoint, role grant, business policy or schema was added. Source is `cloudflare/workers/src/auth-invalidation.ts`, used by password-change, password-recovery, account-management and auth logout.
